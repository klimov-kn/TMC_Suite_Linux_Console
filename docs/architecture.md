# Архитектура порта: ядро vs MFC

## Проблема

Программы TMC Suite (включая счётные ядра PlanarRT_H/X) построены на **MFC** — это
GUI-фреймворк Microsoft, существующий только под Windows. Под Linux MFC **нет и не
будет**. Поэтому портирование ядра — это не «перекомпилировать», а **отделить
вычислительную часть от MFC-обёртки** и обернуть её в консольное приложение.

## Что внутри ядра (предстоит подтвердить инвентаризацией)

Типичная структура MFC-ядра TMC Suite:

```
┌─────────────────────────────────────────────┐
│  MFC-обёртка (Windows-only) — ВЫРЕЗАЕМ        │
│  • CWinApp / InitInstance                     │
│  • окна, диалоги, ресурсы .rc                 │
│  • реестр Windows (SetRegistryKey, MRU)       │
│  • win32 API                                  │
├─────────────────────────────────────────────┤
│  Вычислительное ядро (чистый C++) — ОСТАВЛЯЕМ │
│  • PlanarRT_H / PlanarRT_X алгоритм           │
│  • complex, prepr, TMCIndan, exprint          │
│  • TMCLibError                                │
│  • SFILE95 — чтение/запись файлов             │
└─────────────────────────────────────────────┘
```

Цель — провести границу: всё ниже линии портируем, всё выше заменяем на CLI.

## Целевая архитектура на Linux

```
                 argv (входной файл, выходной файл, параметры)
                          │
                  ┌───────▼────────┐
                  │   src/cli/      │   парсинг аргументов, запуск расчёта,
                  │ tmc_rth/tmc_rtx │   коды возврата, сообщения (заменяет MFC main)
                  └───────┬────────┘
                          │
                  ┌───────▼────────┐
                  │   src/core/     │   вычислительное ядро (ОБЩЕЕ с Windows,
                  │  математика     │   математику НЕ трогаем)
                  └───────┬────────┘
                          │
                  ┌───────▼────────┐
                  │  src/compat/    │   слой совместимости:
                  │                 │   • фикс. типы для файлов (int32_t…)
                  │                 │   • файловый IO вместо win32/MFC
                  │                 │   • заглушки win-типов (если остались)
                  │                 │   • CP1251-поля как сырые байты
                  └───────┬────────┘
                          │
                  библиотеки-математика (.a):
                  complex, exprint, prepr, TMCIndan, TMCLibError, sfile95
```

## Принцип разделения слоёв

- **`src/core/`** — вычислительная логика. В идеале **не редактируется вообще** или
  только минимально (замена `long`→`int32_t` в форматах — см. binary-compat). Источник
  истины — `../TMC_Suite/src`.
- **`src/compat/`** — весь «клей», который позволяет ядру жить без Windows. Здесь
  изоляция всех `#ifdef _WIN32` / замен MFC.
- **`src/cli/`** — две тонкие точки входа (H и X), читают аргументы, вызывают ядро.

Такое разделение оставляет дверь открытой для **этапа 2027 (GUI)**: ядро как
библиотека отделено от способа запуска, поверх него позже можно поставить Qt-интерфейс.

## Зависимости (из Windows-проекта)

Счётные ядра линкуются с: **sfile95, prepr, exprint, TMCIndan, TMCLibError**
(+ complex как зависимость). Эти библиотеки собираем под Linux первыми (Фаза 3
в [../ROADMAP.md](../ROADMAP.md)).

## X-мода: 6 макросов препроцессора

Как и в Windows-проекте, `tmc_rtx` требует 6 макросов, задаваемых **в настройках
сборки** (в CMake — через `target_compile_definitions`), а НЕ в общих заголовках:

```
ELECTRON_Q___  ELECTRON_M___
CTMCRTH_INDANBLCK_FILEY     CTMCRTH_INDANBLCK_RECTSTATY
CTMCRTH_INDANBLCK_CIRCSTATY CTMCRTH_INDANBLCK_POLYGSTTY
```
