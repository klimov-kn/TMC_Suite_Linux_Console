# Многопоточность, память и большие области

## Исходные данные (ответы заказчика)

- Сервер: **32 ГБ ОЗУ**, один узел (#12).
- Запуск из консоли, **без планировщика** (#11).
- Задачи — **большие области** (#15).
- MPI/распределённый счёт — **не нужен** (вывод из #11–13).
- Многопоточность в программе «вроде есть» (#14) — проверить по коду.

## Стратегия параллелизма

**Только в пределах одного узла → OpenMP.** MPI (распределение на много узлов) НЕ
делаем: машина одна, заказчик распределённый счёт не запрашивал, а MPI — это отдельная
крупная переработка ядра.

```
Один сервер, 32 ГБ
   └── tmc_rth / tmc_rtx
         └── OpenMP (несколько потоков на ядрах CPU)   ← если уже есть/нужно
   ✗ MPI между узлами — вне проекта
```

### Что проверить про текущую многопоточность (Фаза 7)

- [ ] Есть ли в коде потоки (Windows: `_beginthread`, `CWinThread`, `std::thread`,
      `#pragma omp`)?
- [ ] Если это **Windows-потоки** — заменить на OpenMP/`std::thread` (Windows API под
      Linux нет). Это «клей», не математика.
- [ ] Управление числом потоков — через `OMP_NUM_THREADS` (стандартно для консоли).

## Память: главное ограничение

«Большие области» против **32 ГБ** — реальный риск нехватки памяти и упора в
32-битную индексацию.

### Что проверить

- [ ] **Индексация массивов.** Если размеры/смещения хранятся в `int` (32 бита, до
      ~2.1 млрд), при больших областях возможно переполнение. Кандидаты на `size_t`/
      `int64_t` — но ⚠️ это касается ВНУТРЕННИХ индексов, НЕ форматов файлов (там
      ширина фиксирована ради совместимости — см. [binary-compat.md](binary-compat.md)).
- [ ] **Пиковое потребление памяти** на реалистичной большой задаче — измерить
      (`/usr/bin/time -v`, `valgrind --tool=massif`), сравнить с 32 ГБ.
- [ ] Нет ли лишних копий больших матриц, которые можно убрать без правки математики.

> ⚠️ Граница: менять **тип индекса ради вместимости** — допустимо (это не формула).
> Менять **порядок/способ вычисления** — нельзя без разрешения (это математика).

## Что уточнить у заказчика

- [ ] Реальные размеры «больших областей» в числах (число узлов сетки / размер
      матриц) — чтобы заранее понять, влезает ли в 32 ГБ (вопрос #15, остался без
      конкретики).
