# Тесты бинарной совместимости

Главный критерий приёмки проекта: выходной файл, посчитанный на Linux, **байт-в-байт**
совпадает с файлом от Windows-версии на том же входе (ответы #8, #16). Здесь — эталоны
и проверка.

## Идея

```
вход (эталонный)  ──►  Windows tmc_rth/tmc_rtx  ──►  выход_win   (эталон)
                  └─►  Linux   tmc_rth/tmc_rtx  ──►  выход_linux
                                                       │
                                          cmp выход_win выход_linux  → должны совпасть
```

## Структура

- **`reference/`** — эталонные пары вход/выход, посчитанные **проверенной
  Windows-версией**. Источник входов — `../../TMC_Suite/samples/SAMPLE_R`.
  Для каждого случая: `<имя>.in` (вход), `<имя>.win.out` (эталонный выход Windows).
- проверка: посчитать вход нашим Linux-бинарником → сравнить с `*.win.out`.

## Как сравнивать

```bash
# бинарные форматы — побайтно:
cmp reference/<имя>.win.out out_linux/<имя>.out

# текстовые форматы — учесть переводы строк (\r\n vs \n) ТОЛЬКО если формат текстовый:
diff <(tr -d '\r' < reference/<имя>.win.out) <(tr -d '\r' < out_linux/<имя>.out)
```

> ⚠️ Если есть заведомо переменные поля (дата/время расчёта) — задокументировать их и
> исключать из сравнения адресно, а не «на глаз».

## Минимальный набор кейсов

- [ ] H-мода: простой случай из SAMPLE_R.
- [ ] X-мода: случай с 6 макросами.
- [ ] POLY.TPL-подобный (устойчивость в double, Баг #11) — должен совпасть с эталоном.
- [ ] «Большая» область (память) — отдельно, в Фазе 7.

Автоматизация — скилл `verify-binary-compat`.
